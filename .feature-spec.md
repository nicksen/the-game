# Modularize the game's JavaScript

## Goal

Turn the 20 plain `<script>` files in `js/` into ES modules with explicit imports and exports, bundled by
`bun build` into one script. The game must keep working everywhere it runs today:

- opening `index.html` straight from disk (`file://`), which the replay test does
- the launcher (`mise run start`) and the compiled executable
- GitHub Pages, including the service worker's offline cache

Why: today every top-level name is a global, load order in `index.html` is the only dependency
management, and oxlint's `no-unused-vars` has to be off for `js/` because it can't see across files.

## Constraints

- Browsers refuse `<script type="module">` on `file://`, so the browser gets one classic script: the bundle,
  built with `--format=iife`.
- An imported binding can't be reassigned by the importer. Top-level `let`s that other files write
  (e.g. `drag`, `shake`, `ctx`/`W`/`H`, `heldProp`, `muted`) or read while they change must live in
  exported objects instead.
- A bundle has its own scope, so modules and plain scripts can't be mixed on the page; the switch from
  scripts to modules happens in one step. Everything before it is done while the files are still plain
  scripts, so the replay test checks each step.
- The replay test (pixel and HUD hashes, frame by frame) must pass after every commit, with the existing
  baseline. Any re-record needs to be explained, as with the prettier reformat.

## Plan

### 1. Shared state into objects (still plain scripts)

One commit per area. The replay must pass after each:

- input: `tool`, `drag`, `pointer`, `heldProp`
- the dummy's condition: `pain`, `hurtT`, `bodyFlash`, `standK`, `combo`, `lastHit`, `lastIdle`, `sessionDmg`,
  `wasDizzy`, `idling`, `blinkT`, `speech`
- screen effects: `shake`, `flash`, `swingT`, `zapT`, `zapTarget`
- canvas: `ctx`, `W`, `H` (reassigned by `rooms.js`)
- settings: `muted`, `lookId`, `roomId`

Rule: a top-level `let` stays a plain `let` only if no other file reads or writes it. Group names into a
few objects by area (e.g. `input`, `dummyState`, `fx`, `view`, `settings`), not one huge `state`.

Also in this step:

- `js/airlock.js` uses `airlockBtn`, the browser's implicit global for an element id. Replace it with
  `document.getElementById('airlockBtn')`.
- `tests/pwa.mjs` reads the game's globals `save` and `B`, which won't exist after bundling. Read coins from
  `localStorage`, as `tests/replay.mjs` does. For the dummy's position, the game exposes a small read-only
  test hook (e.g. `window.__dummy = () => ({ x, y })`), like the replay test's `window.__frame`.

### 2. Switch to modules and the bundle (one commit)

- Add `export` to every name used by another file and `import` lines where they're used. Function bodies
  don't change.
- Entry point: `js/main.js`. It calls `boot()`, and `js/pwa.js` is imported for its side effect.
- There are import cycles (e.g. dummy ↔ furniture, audio → hazards → … → audio). They're fine as long as
  nothing reads a cyclic import while the module is still loading. That would throw at load time and fail
  every test, so it can't slip through. Move any such top-level use into a function.
- New task `mise run bundle`: `bun build js/main.js --format=iife --outfile build/game.js` (not minified, so
  the shipped code stays readable). `build/` is gitignored.
- New task `mise run watch`: the same build with `--watch`, for editing with the page open from disk.
- `index.html` loads the single `build/game.js`. Remove the comment about script order.
- Wire up `build/game.js`:
  - `GAME_FILE_PATTERNS` in `launcher/embed-game.ts` lists `build/game.js` instead of `js/*.js`, which feeds
    the executable and `_site/`
  - `sw.js` needs no change, because it finds `src="build/game.js"` in `index.html`
  - `start`, `build`, `site`, `test`, `test:pwa`, `test:exe` and `test:update` depend on `bundle`; the
    `build` task's `sources` stays `js/*.js` and adds `build/game.js`
  - `.prettierignore` and `.oxlintrc.json` ignore `build/`

### 3. Turn `no-unused-vars` back on for `js/`

- Remove the override in `.oxlintrc.json`.
- Fix what it finds: dead code and unused exports. Keep this separate from step 2 so the switch stays
  mechanical.

## Acceptance criteria

- [ ] `js/*.js` are ES modules; no file relies on another file's global
- [ ] the page loads one script, `build/game.js`
- [ ] `mise run test` passes against the current baseline
- [ ] `mise run test:pwa` passes, including the offline check, and no longer reads game globals
- [ ] `mise run test:exe` passes
- [ ] `mise run site` produces a working `_site/`
- [ ] `mise run lint` passes with `no-unused-vars` on for `js/`, and `mise run format:check` passes
- [ ] opening `index.html` from disk works after `mise run bundle`

## Out of scope

- TypeScript, minification, source maps
- changing game behaviour or reorganizing code beyond what modules require

### Decisions

- Imports are live bindings, so only variables written from another file needed changing (20 of them), not
  every shared `let`. Each moved to its only writer, got a named function in its owner, or (screen effects,
  where some writes set exact values) went into an object.
- `airlockBtn` already used `getElementById`; nothing to do.
- The pwa test taps where the dummy starts instead of reading its position through a test hook, so the game
  has no test-only code.
- Imports and exports were generated from scope analysis. The bundle runs modules in a different order than
  the old script tags, which is safe because no module reads another's value while loading; the replay
  matches the original baseline unchanged.
- Room thumbnails aren't covered by the replay, so each step was also checked against `main` with time and
  randomness frozen.
- The service worker now caches 7 files instead of 26.
