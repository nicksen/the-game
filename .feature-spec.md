# Convert the game to TypeScript

## Goal

Write the game's modules in TypeScript and check their types in CI, ending with `strict` on. The browser
still gets the one bundled script, `build/game.js`, so `index.html`, `sw.js`, the launcher, the executable
and GitHub Pages don't change.

Why: the game passes plain objects between modules (body points, furniture, hazards, particles), and nothing
checks their shape today. Types document those shapes and catch mistakes the replay test can't point at.

## Findings

Measured on a renamed copy of `js/`:

- not strict: 121 errors, nearly all objects that gain properties after they're created (`const B = {}`
  filled in by `buildDummy`), plus a few loose-but-working spots: numbers assigned to `textContent`, and
  `noise()` called without its optional last argument
- `strict`: 935 errors, adding untyped parameters (about 230), `getElementById` results that may be `null`
  (about 55), and `let x = null` variables whose type becomes `null`
- the launcher and `tools/build-site.ts` already pass `strict` with Bun's types
- none of the errors looked like a real bug

## Constraints

- Bun builds TypeScript but doesn't check types, so type checking is a separate `tsc --noEmit` step.
- Types are removed at build time, so the replay test (pixel and HUD hashes, frame by frame) must pass after
  every commit with the existing baseline, and room thumbnails must match `main`, as in the module work.
- Work on `main`, no branch (see `CLAUDE.md`). Every commit passes lint, format, the replay and, once it's in
  CI, the type check.
- TypeScript guidelines: named exports only, no barrel files, never `as unknown`; fix types rather than cast.

## Plan

### 1. Tooling

- Add `typescript` and `@types/bun` as dev dependencies.
- `tsconfig.json`: `noEmit`, `moduleResolution: "bundler"`, `allowImportingTsExtensions`, `lib` ES2022 + DOM,
  `types: ["bun"]`, covering `src/`, `launcher/` and `tools/`. Start with `strict: false`.
- New task `mise run typecheck`: `tsc --noEmit`. It joins CI once it passes (end of step 2).

### 2. Rename and type the core data (not strict)

- Move `js/*.js` to `src/*.ts`; `.ts` files in a folder called `js/` would be confusing. Imports become
  `./canvas.ts`. Update the `bundle` and `watch` tasks (entry `src/main.ts`, sources `src/*.ts`).
- The rename commit keeps the code as it is, so it type-checks with errors; CI doesn't run the type check
  yet, and the replay still has to pass.
- Fix the 121 errors by declaring types for the shared data, each next to the module that owns it:
  - the dummy: `Point`, `Stick`, the named body points `B`
  - furniture: prop specs and props
  - rooms, tools and looks tables
  - hazards: bombs, pianos, projectiles, couches, the zap target
  - effects: particles and floating texts
  - vikings, the airlock, the save, speech
  - the loose spots: `String(...)` for `textContent`, an optional parameter for `noise()`
- One commit per area, then a commit that adds `mise run typecheck` to CI.

### 3. Turn on strict, one check at a time

`strict` is several checks; turn them on separately so each change stays reviewable:

1. `strictNullChecks`: type the `let x = null` variables, and handle possibly missing DOM elements. Elements
   the page always has can use a small `byId(id)` helper that throws if the element is missing, rather than
   `!` everywhere.
2. `noImplicitAny`: type the remaining parameters, file by file, smallest files first and `hazards.ts` last.
3. the rest of `strict`, then replace the separate flags with `"strict": true`.

Each check is turned on in the same commit as the last fix it needs, so CI stays green. Fixes before that
are plain commits that also pass.

## Acceptance criteria

- [ ] the game's source is `src/*.ts`; no `.js` left in it
- [ ] `tsconfig.json` has `"strict": true` and `mise run typecheck` passes
- [ ] CI runs the type check before publishing
- [ ] no `as unknown`, no `any`, and `!` non-null assertions only where a comment says why it's safe
- [ ] `mise run test`, `test:pwa` and `test:exe` pass against the current baseline; thumbnails match `main`
- [ ] `mise run lint`, `format:check` and `site` pass

## Out of scope

- typing the tests (`tests/*.mjs`) and `tools/make-icons.mjs`
- changing game behaviour or restructuring code beyond what the types need

### Decisions

- Two type-check projects: `src/tsconfig.json` uses browser types only, and the root `tsconfig.json` covers the
  launcher and tools with Bun's types. With both in one project, `setTimeout` had Bun's return type in the game.
- `byId(id, ElementClass)` and `context2d(canvas)` check at runtime and throw, instead of casts or `!`.
- Rooms and tools take their types from their tables (`(typeof ROOMS)[number]`), so they aren't declared twice.
- Projectiles are built with a shared `flying()` helper, and only meteors carry a landing spot `tx`, so the
  type needs no cast.
- The one remaining cast is `B`, the dummy's named body parts, filled in by `buildDummy()` before any read.
- Small behaviour-neutral edits the types asked for: strings instead of numbers for `textContent` and
  `style.opacity`, props start with `gx`/`gy` of 0, `shadeRGB` builds its tuple directly, `wiggle()` checks for
  an `HTMLElement`.
- No game code was found to be wrong; the replay matched the original baseline after every commit.
